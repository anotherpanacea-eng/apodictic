# PDF annotation proofing — optional internal navigation

**Status:** Proposed (unbuilt). Specification only; runtime activation and reader qualification require later reviewed work.

## Purpose and boundary

Existing PDF proofing places visible manuscript markers and verbatim comments in Findings. This increment lets a reader click each marker to its own comment and each comment chunk back to its marker. The gated manifest and snapshot remain authoritative. No diagnosis, ranking, comment rewriting, new manuscript interpretation, model/SETEC calls or workflow activation is added.

Source baseline: `annotation_export.py` at `6615086379a7df372602cc22162db79333528f03`. PDF export Increment 5 is built; navigation is proposed. A later build must update this status and ROADMAP together. `_pdf_navigation_layout` is the proposed shared layout helper/build marker, not an existing symbol.

Extend `build_pdf(manifest_obj, snapshot, *, internal_links=False)` and `check_pdf(manifest_obj, snapshot, pdf_bytes, *, internal_links=False)`, preserving return shapes. Default false preserves existing bytes, callers, filenames, text streams, fixtures and P1–P3 behavior. Current `_resolve` selects newest inputs and does not itself enforce this full boundary; default behavior remains unchanged.

Explicitly recognize `--internal-links` for exporter generation verb `pdf` and validation verb `pdf-export`. Pass the declared mode through generation, preconditions and P1 fresh build. Current main dispatch removes flag-shaped arguments; adding a keyword alone cannot activate navigation. Reject repeated/misplaced navigation flags, including on other export targets, with usage exit 2. Preserve unrelated legacy CLI behavior. Opt-in must never silently generate or validate default mode. The shell `pdf-export` wrapper in `plugins/apodictic/scripts/validate.d/commands-b.sh` must pass this mode through and refuse nonzero with a named validation-unavailable error when Python or the helper is missing. Its current advisory success fallback is retained only for default mode. Validate misplaced/repeated navigation flags even on unavailable-helper paths; no degraded self-test may qualify navigation.

Navigation generation/validation use separate `pdf-linked/` output with the existing filename convention; default `pdf/` remains untouched. For navigation mode require exactly one matching manifest, snapshot and (on validation) linked PDF; refuse ambiguous selections instead of current newest-file behavior. Resolve their real paths within the operator-selected run folder, reject symlink escapes, and contain output paths at use time, with no cross-mode fallback. ## Layout and ownership

One authoritative emitted-item sequence retains semantic ownership alongside unchanged shown text: title, spacers, marked manuscript lines, Findings header, sorted findings, 90-character comment chunks and trailing spacers. At this baseline item index `i` has page `i // 45`, slot `i % 45`, baseline `734 - 14 * (slot + 1)`, x=72, Helvetica size 11, page 612 by 792 points. Every item advances a line, including spacers; manuscript blank lines remain shown empty strings. Positions cannot be computed from shown strings alone.

Retain each manifest finding's identity through insertion and comment chunking. Marker positions come from insertion records in final marked text after all preceding insertions, not unadjusted source offsets. Co-located anchors produce separate adjacent markers in actual final splice order. Overlapping source spans are allowed when rendered marker regions remain distinct. Comments may lack their own ID or mention other IDs; regex-searching comment prose does not establish navigation ownership.

Each manuscript marker has exactly one forward link to its own first visibly inked comment chunk. Each visibly inked Findings chunk has one return link, including on later pages. Blank/whitespace-only chunks have no hit region. Reject non-string or empty/whitespace-only comments in navigation mode: they provide no visible destination. No-findings input is valid with zero links, explicitly reported as zero findings, without implying viewer support. Empty snapshots or anchors after a final newline require a proven visible marker in the actual emitted sequence or named refusal; do not fabricate a line or drop a marker.

## Exact geometry

Map emitted CP1252 bytes through PDF 1.4 Appendix D WinAnsi glyph names, then through pinned Helvetica AFM advances (`WX`) and ink boxes (`B`). AFM codes use AdobeStandardEncoding, so indexing them directly with CP1252 bytes is wrong. Measure each prefix before a marker. Character counts, PDF escape lengths, average widths, platform fonts and runtime downloads are prohibited substitutes. Apply actual text state: size 11, fixed baseline, `Tj` with no kerning adjustments. Refuse control/undefined glyph mappings or missing metrics anywhere affecting a linked region's position or ink. Default encoding behavior stays unchanged.

Scale/translate glyph ink boxes using accumulated advances and baseline. The hit rectangle is the smallest axis-aligned bounding rectangle enclosing the valid translated glyph ink boxes, including inter-glyph whitespace, with no arbitrary padding. Only explicitly mapped whitespace may advance without ink. A non-whitespace glyph with missing, empty or untrustworthy ink bounds refuses wherever geometry is needed, including mixed text: the pinned AFM Euro entry has zero ink bounds, so a comment such as `i€` cannot silently omit that glyph. This data limitation does not change default PDF encoding acceptance. At fixed size 11, use integer thousandths of a point (`11 * AFM_units`) plus the integer origin/baseline in thousandths. Serialize exact decimal thousandths with no rounding or padding; locale/float formatting cannot shift coordinates. Require finite positive-area rectangles wholly inside MediaBox. The rectangle encloses measured ink; it need not be a subset of the disjoint glyph ink union. Refuse clipped markers or comment chunks, missing ink and positive-area overlap between distinct hit rectangles on a page. Boundary touching is allowed. Never clamp, shorten, omit required links, invent widths or reflow text to avoid refusal. Existing unlinked prose may retain long lines; every linked region and destination must be contained.

The destination is the top-left corner of the measured target ink rectangle, contained in its page. Use explicit actual page-object references and `/XYZ left top null` to retain zoom. Resolve page objects from shared layout rather than an independently guessed object schedule.

## PDF structure

Stay within PDF 1.4. Append deterministic Link objects after the existing font object, ordered by emitted item then marker position. Each reference occurs only in its containing page's `/Annots`. Use `/Type /Annot`, `/Subtype /Link`, `/Rect`, `/Border [0 0 0]` and direct `/Dest` arrays. Forbid `/A`, `/AA`, external URLs/files, JavaScript, Launch, external destinations, sticky-note content and PDF 2-only features/QuadPoints. Retain page/content/font order, correct xref offsets and trailer Size, without timestamps, random IDs or compression drift. Navigation changes structure only: decoded text and page partition equal default mode on inputs accepted by both.

## Metrics and technical evidence

Pin the Adobe-authored [preserved Helvetica AFM](https://raw.githubusercontent.com/tecnickcom/tc-font-core14-afms/main/Helvetica.afm), SHA256 `da33f1870474c8e68bfe3e2353ff107ab6c6eea1f9836ce2aaf1e1a07b17982f`, and its [accompanying license](https://github.com/tecnickcom/tc-font-core14-afms/blob/main/LICENSE). A later build vendors required data with inspectable generation recipe, original notices, source checksum and glyph mapping provenance. Verify redistribution terms for exact included bytes; mark modifications as required. Missing/unverifiable source or license blocks build; invented official data is prohibited. This specification vendors no metrics or runtime dependencies.

The Adobe-authored [PDF 1.4 Reference, MIT mirror](https://stuff.mit.edu/afs/sipb/contrib/doc/specs/software/adobe/pdf/PDFReference.pdf), sections 8.2.1/8.4 and Appendix D, provides internal destination, annotation and encoding semantics. The [Adobe AFM specification](https://adobe-type-tools.github.io/font-tech-notes/pdfs/5004.AFM_Spec.pdf) defines metrics. Feasibility is not universal reader support.

## Validation and later acceptance

P1 compares bytes to a fresh build in the explicitly selected mode. A refused fresh build is blocking, never grounds to skip P1. Retain P2 manuscript round-trip and P3 marker/comment fidelity. Add independent structural diagnostics against authoritative manifest/layout: exact forward/return coverage, no extras, page ownership, destination identity, finite contained geometry, correct object/xref structure and forbidden-action absence. Comparing artifact self-reports to themselves does not verify ownership. Diagnostics identify finding/condition without copying prose.

Later tests use invented fixtures and PDF structure semantics, not source-text assertions:

- Default bytes and repeated navigation determinism; identical decoded text/page partition across modes.
- Unequal-width prefixes (`W` versus `i`), CP1252 punctuation, escaped parentheses/backslashes, controls, missing glyph metrics and mixed-Euro text with untrustworthy ink bounds.
- Co-located markers, overlapping source anchors, page-boundary/multi-page comments, decoy IDs, blank chunks and zero findings.
- Clipped long-line markers/wide comments, final-newline anchors, empty snapshots, malformed annotations/comments, conflicting or malformed second annotation blocks, and existing-output preservation on refusal.
- Missing/extra/tampered links, wrong page/destination, overlapping/out-of-page rectangles, forbidden actions and mode mismatch; independent checks fail as well as P1.
- CLI and shell-wrapper mode propagation, misplaced/repeated navigation flags, absent Python/helper refusals, unique selection and no default-directory fallback.

Structural validation is separate from reader qualification. A later qualification record identifies reader/version/platform, exact artifact checksum and observed forward/return behavior on single-page, adjacent-marker and cross-page fixtures. At least one named reader must pass before advertising qualified navigation; document unsupported readers. The [PDF Association report on preview limitations](https://pdfa.org/googles-pdf-preview-fails-including-with-pdfs-made-by-google-docs/) motivates this independent evidence. Unperformed checks are not passes; no all-viewers claim.

Excluded: font embedding, Unicode expansion, reflow, tagged-PDF/PDF-UA conformance, editor integration, corpus acquisition and reader-automation infrastructure. Later implementation follows independent reviews, local gates and normal draft/train admission.
