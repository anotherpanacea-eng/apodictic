# Research response evidence — proposed producer contract

**Status:** Proposed (unbuilt).
<!-- built-when: plugins/apodictic/skills/research-verification/scripts/provenance.py contains "def save_response_evidence" -->

## Purpose and boundary

The Citation Verifier requires the API responses used in resolution to be stored as JSON intermediates. It also requires failed tier checks to be visible before a source is called unretrievable. Today `academic_apis.py` parses responses and the resolver records selected summaries in `ProvenanceStore`; `ResponseCache` supports operational reuse. A summary entry or cache hit alone cannot reproduce the provider JSON used for a decision. This increment gives an explicitly opting-in Python caller a complete, detached record of the parsed JSON and final resolution-path receipts. It does not enable automatic retention in the CLI.

The guarantee covers calls made through `resolve_citation(citation, cache, provenance, ledger=...)` when `provenance` is evidence-enabled, and `resolve_batch(citations, ..., response_evidence_path=...)` when that path is supplied. It covers the Crossref DOI and search, Unpaywall, Semantic Scholar search, OpenAlex search, CORE search, direct URL check, and Wayback availability branches that the resolver actually visits. It includes each final branch outcome, including a search with no match, a valid empty response, a failed request, a malformed response, and a budget or circuit skip. Each observed value or terminal receipt gets an event, including one rejected cache value followed by a fresh value in the same tier; unvisited tiers have no event. Complete JSON snapshots apply to admitted parsed responses and unambiguous cached JSON values. A legacy cached `_error` or `_skipped` object with unknown origin gets the bounded ambiguity receipt defined below. Standalone `check_retraction`, `check-url`, provider helper calls, `get_s2_citations`, and direct `_fetch_json` calls have no evidence guarantee under this increment. Retry history is outside the guarantee; a final request failure gets one receipt.

This is a producer capability. The presence of an exported file does not certify a citation verdict, source content, or suitability of the evidence for any downstream publication or admission rule.

## Caller API and compatibility

`ProvenanceStore(record_responses: bool = False)` enables in-memory response evidence only when explicitly constructed with `True`. A caller passes this store to the existing `resolve_citation` signature. `provenance.response_evidence()` returns a detached Python copy of the evidence document; `provenance.save_response_evidence(path: str)` writes that document as UTF-8 JSON to the caller's explicit path and returns the path after a complete successful write. Calling either evidence method on a disabled store raises a clear `RuntimeError`; it cannot return an apparently complete empty run. An enabled store with no visited tiers may legitimately export `events: []`. The caller decides if, where, and how long to retain it. An evidence-enabled store without a save call retains evidence only in that process. `ProvenanceStore.save(path)` keeps its legacy summary format and purpose.

`resolve_batch` adds a keyword-only `response_evidence_path: str | None = None`. With a path, it constructs an evidence-enabled store and saves its response-evidence document before writing or printing the ordinary batch result. It returns the same batch-result shape and meanings as before. On successful export, the caller has the separate evidence file at the supplied path; there is no implicit directory or filename. Before resolution or writes, the opt-in path is rejected with `ValueError` if it aliases `output_path` or the active `sidecar_dir/Citation_Reliability.json` destination. Compare normalized absolute paths after resolving existing ancestor symlinks, and use filesystem identity for existing symlinks/hardlinks; relative spellings and aliases to the same destination must not pass. There is no claim to prevent a concurrent actor from changing those paths after preflight. No CLI flag is introduced by this contract. With `record_responses=False` and `response_evidence_path=None`, CLI arguments, returned keys, printed output, default cache and provenance formats, network behavior, and storage behavior retain their meanings. The separately reviewed malformed-input normalization below applies uniformly to both modes.

Evidence events are held separately from the existing `provenance.entries`. Existing `prov-N-source` IDs, their sequence, `result.provenance_refs`, confidence ceilings, batch keys, ledger coverage, and strict halt meaning do not change. A new event may point to an existing `prov_ref`; collecting previously unrecorded empty/failure paths must not insert legacy provenance entries or renumber those refs. Evidence capture must observe the same resolution decisions whether enabled or disabled. A separately reviewed, finite malformed-response normalization is therefore a prerequisite to the runtime evidence capability: for covered fields the resolver actually reads, an invalid API shape must yield `not-checked` if the citation remains unresolved, with the tier in `not_checked_providers`, in **both** modes. That correction may turn a previously misclassified `not-found` or an uncaught shape exception into `not-checked`; it is an explicit malformed-input compatibility exception, not evidence-mode behavior. Valid responses retain their prior resolution behavior and result-key meanings. Duplicate `ref_id` values remain legal; `citation_index` distinguishes them in batch output.

## Evidence document and exact representation

The exported document is one JSON object with `schema: "apodictic.response-evidence.v1"` and `events` in resolver observation order. Each event has `event_id` (run-local `response-1`, `response-2`, ...), `citation_index` (zero-based in a batch; `null` for direct `resolve_citation`), `ref_id`, `source`, `kind`, `outcome`, `origin`, `observed_at`, `recorded_at`, and `prov_ref` (the existing summary ref if one was emitted, otherwise `null`). These fields link a decision to its attempted tier without relying on a possibly duplicated citation ID. Time values, when known, are UTC RFC 3339 strings; `recorded_at` is the time the event is captured during this resolution, and is never described as the original HTTP retrieval time.

For `kind: "json_value"`, the event additionally contains `representation: "parsed-json-value-v1"`, `payload` (the complete detached JSON value the resolver received), and `payload_sha256`. For a fresh request this is the complete parsed provider response. For cache reuse it is the cached JSON value actually used; a legacy cache's fidelity to an earlier provider response is unknown. The admitted value domain is recursive and acyclic: `null`, booleans, integers, finite floats, strings containing Unicode scalar values (no lone surrogates), arrays represented by Python `list`, and objects represented by Python `dict` with string keys. Nested values obey the same rule. Tuples, non-string object keys, sets, custom objects, cycles, `NaN`, and infinities are invalid received values, even if `json.dumps` would coerce some of them. Validate this domain **before** copying or hashing. The hash domain is exactly the UTF-8 bytes of the detached `payload` encoded with Python `json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False)`. Arrays keep their order; object keys are sorted for this digest. The export may use indentation, but a verifier recomputes the digest using this rule after loading the export. The digest binds the parsed JSON value, **not** the original HTTP body. Whitespace, duplicate object-key spellings, number lexemes, and byte encoding from the HTTP body are not recoverable from parsing. Do not label this payload or hash “wire bytes,” “HTTP-body hash,” or a verbatim raw response.

Capture the provider value at the requester/cache handoff, before a helper's `or {}` fallback or Wayback validation can replace it, and before resolver interpretation or caller mutation. The requester must distinguish a parsed provider object that happens to contain `_error` from a locally constructed `_error` sentinel, even if both keep the same resolver behavior. A syntactically valid JSON value of the wrong API shape is still captured in full, with `outcome: "invalid"`; the uniformly normalized resolver treats that attempted tier as `not-checked` if it remains unresolved. This includes top-level `null`/arrays and wrong nested container shapes that otherwise make resolver field access fail. The prerequisite guard checks only the API containers and fields the covered resolver path actually accesses, whether the value came from a request or cache; it is not a comprehensive provider-schema framework. A JSON syntax or UTF-8 decoding failure, non-JSON body, or value outside the admitted JSON domain has no `json_value` claim. A fresh request yields `kind: "request_failure"`, `outcome: "invalid"`, and a bounded error category receipt without the body. A cache value outside the domain yields `kind: "cache_invalid"`, `outcome: "invalid"`, `origin: "legacy_cache"`, and `observed_at: null`; it cannot be coerced into a provider snapshot or treated as absence in either mode. Unsupported values must never be converted with `default=str` or silently truncated. Once an admitted value has passed domain validation, failure to detach, serialize, or hash it is an evidence-collection exception, not a successful evidence event or export. The store then becomes incomplete and refuses subsequent `response_evidence()` or `save_response_evidence()` calls, so an earlier partial sequence cannot masquerade as a complete run.

The event's `outcome` is the final disposition of this observed value or tier receipt: `selected` when this response supplied resolved metadata, an accepted Unpaywall OA location, or archive availability; `empty` when valid provider JSON contained no candidate, no OA location, or no archive snapshot; `no_match` when candidates existed but none was accepted, including a DOI mismatch or unusable OA candidate; `invalid` for unusable JSON or API shape; `unclassified` when a legacy cache marker cannot be attributed to provider JSON or a local sentinel; `failed` for terminal transport/HTTP failure; `skipped` for a pre-call budget/circuit decision; and `probe_live`, `probe_dead`, or `probe_incomplete` for a direct URL check. A valid provider JSON event is retained even if a later tier resolves the citation. Unpaywall enrichment is recorded even if it does not alter `resolution_status`. An empty provider response and an unavailable Wayback snapshot are observations about that endpoint, not proof that the work itself does not exist.

For `kind: "request_failure"`, `"cache_invalid"`, `"cache_unclassified"`, `"skip"`, or `"url_probe"`, there is no `payload` or `payload_sha256`. Fresh failure, skip, and probe receipts have `origin: "local"` and `observed_at: null`: `recorded_at` dates the receipt, but there is no successfully parsed response retrieval time to assert. A final HTTP or transport failure records only the terminal status/error information the requester actually knows; no HTTP error body is fetched for evidence. A syntactically malformed response records a parse-failure receipt, without invented JSON. A `skip` records the provider and reason category before any call. A direct URL check records the existing derived method/status/error/redirect result as a probe receipt, without reading the source page body or calling it provider JSON. An error sentinel reused from the existing memory-only cache is a `request_failure` with `origin: "cache"` and no asserted retrieval time; it is not a second network failure. If a legacy cache contains a JSON object with `_error` or `_skipped` but no trusted origin metadata, emit `kind: "cache_unclassified"`, `origin: "legacy_cache"`, `outcome: "unclassified"`, `observed_at: null`, and reason `unknown-marker-origin`. This does not declare the cached JSON invalid. Its origin as provider JSON versus a local sentinel cannot be inferred, and a local sentinel may contain a full request URL; this narrow ambiguous-cache case has a receipt rather than a complete JSON snapshot. It must not be claimed as retained provider JSON, and its missing payload remains an explicit evidence gap. A receipt may include bounded, non-secret diagnostic fields needed to explain the outcome; it must not automatically copy request headers, API keys, contact parameters, or a full request URL. If an error message or URL might contain such material, export a stable error category and safe status instead.

## Origin, cache, and time

`origin` is `fresh`, `cache`, `legacy_cache`, or `local`. A fresh `json_value` event has `observed_at` set when that final parsed response is received. A cache hit has `origin: "cache"`; `observed_at` is the known original parse time only when a prior evidence-enabled insertion stored that time together with a digest matching the current cached payload. This origin metadata may be added to the existing successful cache envelope in opt-in mode. Cache `get` still returns only the payload, and existing TTL logic still uses `_cached_at`; that stamp is cache insertion/freshness time, not proof of HTTP retrieval. Legacy envelopes and unwrapped cache entries carry `origin: "legacy_cache"` and `observed_at: null`, even if `_cached_at` exists. A changed payload or missing/mismatched origin binding also has unknown origin time; it can still be snapshotted as the value used, explicitly marked `legacy_cache` for this contract. Do not manufacture a retrieval time from export or cache insertion time, and do not refetch solely to repair missing evidence metadata.

Each use of a cached value creates a distinct event for that citation, with its own `recorded_at` and `citation_index`; identical values may have the same digest. The event owns a deep, detached snapshot of the value seen by that resolver branch. Mutating the result, cache object, or original response after capture cannot change a prior event or its digest. An in-memory cache hit after mutation records the value actually seen on that hit; its origin time is unknown if it no longer matches the origin binding. If a malformed Wayback cache hit is rejected and the existing resolver proceeds to a network fetch, record the rejected cached value with `outcome: "invalid"` **and** the fresh outcome as two ordered events for that tier. This preserves the observed negative path without adding a call. Existing cache TTL, hit/miss accounting, error-memory-only rule, request budgets, circuit behavior, retry count, and rate limiting keep their meanings. An expired cache item that triggers the ordinary fetch produces a fresh event; no event is fabricated for the discarded stale item.

For example, one event in a synthetic title-search run can be:

```json
{
  "event_id": "response-1",
  "citation_index": 0,
  "ref_id": "C-1",
  "source": "crossref-search",
  "kind": "json_value",
  "outcome": "empty",
  "origin": "fresh",
  "observed_at": "2026-01-01T00:00:00Z",
  "recorded_at": "2026-01-01T00:00:01Z",
  "prov_ref": null,
  "representation": "parsed-json-value-v1",
  "payload": {"message": {"items": []}},
  "payload_sha256": "6d1de31f91cbbc99224e6b29e86f303ab618e96f8f792819310f6bc49ddfba48"
}
```

The digest is for the UTF-8 text `{"message":{"items":[]}}`. An absent `prov_ref` here means the legacy summary store did not issue a ref for this empty search; the evidence event still records the attempted tier.

## Export and failure semantics

`save_response_evidence` serializes and verifies every event's supported JSON value before reporting success, writes a temporary file beside the caller's target, then atomically replaces that target. On serialization, temporary-write, or replacement failure it raises an exception, makes a best-effort removal of the temporary file, and does not report retained evidence; an existing target remains intact if failure occurs before replacement. A successful replacement is the commit point: the complete evidence document is now at the target, and no later cleanup error may reverse or misreport that success. In batch mode, evidence export failure propagates before the ordinary result file is written or success is printed. If a later ordinary result or sidecar write fails, the already committed evidence document remains valid, but the batch operation reports its later failure. No result or legacy provenance field claims that an absent or failed evidence file was retained. The caller is responsible for the target location and any policy for access, distribution, size, and lifetime; this contract chooses none.

## Source seams and behavioral acceptance

The requester in `academic_apis.py` must expose the final parsed value or terminal failure to evidence capture before provider-specific validation changes it. The resolver records one event per observed requester/cache value or terminal receipt, including cache hits and negative outcomes; its outcome describes any later local rejection or sentinel substitution. `ResponseCache` may carry optional, digest-bound origin metadata without changing `get`'s payload return or the no-sticky-error/TTL rules. `ProvenanceStore` owns detached event snapshots and export while leaving summary entries and IDs alone. This can be implemented within these seams; no global collector, provider framework, new storage subsystem, or consumer integration is part of the contract.

Offline synthetic acceptance must establish all of the following:

1. A Crossref DOI hit with a nested correction/retraction field exports the entire parsed object, binds the `selected` event to its existing `prov_ref`, and leaves the legacy result/provenance output unchanged when evidence is disabled. Evidence methods on a disabled store raise; an explicitly enabled empty run may export `events: []`.
2. A title search returning `{"message":{"items":[]}}` produces an `empty` provider JSON event; a nonempty search without an accepted candidate produces `no_match`. Subsequent tiers retain their own events. An unresolved citation has enough event receipts to distinguish `not-found` from `not-checked` without converting an error or skip into absence.
3. A terminal 503 and JSON syntax error produce `failed`/`invalid` failure receipts. Syntactically valid wrong-shape Crossref and Wayback objects remain complete `json_value` events with `outcome: "invalid"`; the separately reviewed normalization makes these tiers `not-checked` without a crash in both enabled and disabled modes. A budget skip has no retrieval time and consumes no network request or budget charge beyond existing behavior.
4. Fresh, in-run reuse, opt-in disk reuse, expired-cache refetch, and legacy cache hit yield the specified origins and times. Two citations reusing one cached response have separate event IDs and citation indices while existing provenance refs retain their sequence. A mutated cache value loses any unsupported origin-time claim and is snapshotted as used. A rejected malformed Wayback cache value followed by a fresh fetch produces two ordered events. A legacy `_error` or `_skipped` value with unknown origin produces only a bounded unclassified-cache receipt, without leaking its possible `_url`, asserting a fresh transport failure, or calling the JSON invalid.
5. Mutating a caller's response or returned document cannot change a prior captured event. Loading the saved document and re-encoding each payload by the stated rule reproduces every digest; two different JSON values with the same summary get different digests. No hash is asserted for a receipt. Synthetic `NaN`, a lone surrogate, tuple, non-string object key, and cycle are rejected as invalid received values; failure while detaching or hashing an otherwise admitted value raises and permanently marks that store incomplete, including if a prior event was captured.
6. A direct HEAD/GET liveness result is a derived `url_probe` receipt and causes no source-body read for capture. Disabled mode makes no extra requests or body reads; enabled mode adds none either. For a given response, both modes have the same resolution status, health interpretation, reliability/strict behavior, and confidence ceiling; the malformed-input correction is uniform.
7. A serialization or file-write failure is surfaced to the caller, preserves any preexisting target before replacement, cleans temporary files as best it can, and never reports a successful evidence export. Destination aliases with the batch output or active reliability sidecar are refused before resolution, including relative, symlink, and hardlink forms. Running without the opt-in leaves the ordinary batch output and saved provenance format unchanged.
